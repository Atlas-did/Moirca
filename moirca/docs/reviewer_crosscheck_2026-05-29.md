# Moirca 逐条对照审查报告（正式版｜2026-05-29）

> 目的：对照 reviewer 的结论，逐条判断“已解决 / 仍然存在 / 表述不准确 / 优先级不高”。

---

## 1. 结论摘要

### 总体判断
- reviewer 的**核心风险判断大体正确**：推荐链路仍有 mock、报告未闭环、图谱未串通、异步持久化未完成、数据库业务写入不足。
- 但 reviewer 对**前端现状的判断存在明显误判**：
  - 旧的 `frontend/` 目录确实是空壳；
  - 但主前端实际在 `app/` 目录中，已存在完整的 React + TypeScript 工程、路由、组件和 API 层。
- 因此，"前端基本没有代码"、"前后端完全没接上" 这两句**不成立**；更准确的说法是：
  - **前端主工程已存在并接入了一批核心 API**；
  - **但产品级闭环仍未完成，尤其是真实推荐、图谱闭环、报告闭环和任务持久化**。

### reviewer 的说法

### 实际情况
这两句**不成立**。当前主前端 `app/` 已经接入了若干关键后端 API。

- 真实情况是：前端已经接通了一批核心接口，但还有一些 P2+ 能力没有形成统一入口。

## 7. P0 / P1 优先级建议

### P0：应优先修复
1. **统一前端工程定位**
   - 明确 `app/` 是主前端，旧 `frontend/` 是遗留壳或历史目录。
2. **把 `/api/recommend` 从 mock 切到真实 Agent1-5**
   - 让推荐结果具备真实证据链。
3. **修复 `run.py` 的启动约束和 `ModelRouter` 启动风险**
   - 避免开发态因缺 key 无法启动。
4. **把 simulation 改成可持久化任务**
   - 重启不丢、可查询状态。

### P1：应尽快补齐
1. **compare 从硬编码改成读数据库/图谱**
2. **chat 接入推荐上下文**
3. **图谱上传→抽取→构图→可视化串联**
4. **report 做成“推荐结果 + 图谱证据 + 可追溯”**
5. **统一时间戳与一些代码质量问题**

---

## 8. 结论

- reviewer 的**核心问题判断**大体正确。
- reviewer 的**前端空壳判断**不准确，因为主前端在 `app/`。
- 当前最准确的结论是：
  - **前后端并非完全没接**；
  - **但真正的产品闭环仍未完成**；
  - **P0 应聚焦“真实推荐 + 持久化 + 启动稳定性”**。
