# 部署与运维（云端）

> 目标：P2 结束时能在云端稳定跑起来，并且可回滚、可观测、可控成本。

## 1. 部署形态

### 1.1 容器化（推荐）
- `moirca-backend`：FastAPI
- （可选）`postgres`：生产数据库（当前策略允许先用 SQLite 云端上线）

（可选）
- `redis`：任务队列/缓存
- `worker`：异步报告生成

---

## 2. 环境变量（建议清单）

后端必需：
- `HOST` / `PORT` / `DEBUG`
- `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL_NAME`

数据库：
- `DATABASE_URL`（生产）
- `DATABASE_PATH`（开发 SQLite）

安全：
- `CORS_ORIGINS`（生产不要用 `*`）
- `SECRET_KEY`（用于签名/加密）

日志：
- `LOG_LEVEL`
- `LOG_JSON=true|false`

---

## 3. 日志与审计（必须）

### 3.1 禁止写入日志的字段
- 成绩明细、身份证/手机号、上传文件内容

### 3.2 建议记录的审计事件
- 数据导入（公开/独家）
- 推荐生成（包含 `data_version`、`rule_version`、`model`）
- 报告生成与下载

---

## 4. 数据备份与回滚

- SQLite（P0-P2）：
	- 将 db 文件放在持久化卷/磁盘上
	- 定期快照备份（例如每日拷贝或云盘快照）
- PostgreSQL（若启用）：每日自动备份 + 演练恢复
- 数据快照（公开数据）按省份/日期版本化
- 代码发布必须可回滚（保留上一版本镜像）

---

## 5. 成本控制建议

- 规则/检索优先，LLM 用于“融合解释与报告润色”，避免每步都调用强模型
- 对长报告生成做异步 + 缓存，重复请求直接返回已有报告
