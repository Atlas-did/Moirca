# Backlog（按阶段可执行任务拆分）

> 你可以直接把本文件内容复制到看板（GitHub Projects/飞书/Notion）。
> 每条任务都带“验收口径”，避免做着做着跑偏。

## P0（第 1 周）：示例 + 数据链路跑通

### P0-1 输出一份可展示示例（最优先）
- 目标：生成 1 份完整示例报告（Markdown）
- 验收：包含决策树路径、Top10、冲稳保、风险提示、对比结论、引用

### P0-2 固化 API 契约（让前端能接）
- 目标：锁定 `/api/decision/analyze` 与 `/api/recommend` 的字段结构
- 验收：提供 10 组样例请求/响应（可用于契约测试）

### P0-3 初始化 DB 与语料库
- 目标：跑通 `scripts/init_db.py`
- 验收：数据库中存在 `wisdom_corpus` 与 `professions` 示例数据

### P0-4 独家数据模板（朋友网络可直接填）
- 目标：给出 CSV/表格模板字段（学校/专业/隐形门槛/转专业难度/毕业去向…）
- 验收：任何朋友 5 分钟能填完 1-2 条

### P0-5 公开数据最小样本（1 省份 3 年）
- 目标：手工/半自动收集一份可用公开数据样本
- 验收：能被推荐接口引用（哪怕只是作为 evidence）

## P1（第 2 周）：决策树端到端可用

### P1-1 决策树答案提交（候选池）
- 新增：`POST /api/decision/answer`
- 验收：返回 `candidate_pool`（专业代码/学校列表/过滤条件）

### P1-2 推荐结果“可解释证据”结构
- 扩展：推荐条目增加 `evidence[]`、`confidence`
- 验收：每条推荐至少 2 条 evidence

### P1-3 对比接口（最小版）
- 新增：`POST /api/compare`
- 验收：输出 3-5 个维度对比 + 风险摘要

### P1-4 最小单测/契约测试
- 验收：关键接口有自动化测试（至少覆盖 10 个样例）

---

## P2（第 3-6 周）：云端 MVP 上线

### P2-1 Agent 框架与并行调度（最小可用）
- 验收：至少跑通 Agent1/3/4 → Agent6 → Agent7 一条链路

### P2-2 报告生成（同步/异步二选一）
- 验收：报告可复用（同输入不重复消耗模型），并记录 data/rule/model 版本

### P2-3 云端部署
- 验收：一键部署文档可复现；CORS 不为 `*`；Secrets 不入库；允许 SQLite 云端部署

### P2-4 端到端性能与失败降级
- 验收：LLM 失败时能降级输出“基础规则推荐 + 明确提示”

---

## 已确认（作为不变约束写入执行）

1. **数据库**：先用 SQLite 云端上线验证，P2 不强制 PostgreSQL
2. **账户体系**：匿名为主（device_hash 或等价标识）+ 可选微信扫码登录
3. **报告导出**：P2 优先 Markdown；PDF 放到 P3

## 仍需后续再定（不会阻塞 P0-P2）

1. 微信扫码登录落地方式：仅用于“找回报告”还是也用于“导出权限/付费”（先不做付费也行）
2. 报告分享：返回 share_link（云端）是否做成公开链接，还是登录后查看（按隐私要求决定）
