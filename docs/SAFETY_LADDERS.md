# 护栏分级表(SAFETY LADDERS)

> 版本:v1.0(2026-09-06,AGENT_06 撰写)
> 上位依据:CONTRACT §a.3(target 语义)、§a.4(readonly/pro 矩阵)、§g.2(AGENT_06 错误处理清单);技术原则 1/8/9。
> 效力:所有 `skills/**/skill.json` 的 `strategy.safety.write_level` 与所有 `prompt.md` 的"安全护栏"节必须与本表一致;`skills/tests/test_skill_format.py` 校验分级词汇。

---

## 1. 分级总表

| 级别 | 名称 | 定义 | 允许的 target | 须确认? | 对应 skill.json `write_level` |
|------|------|------|---------------|---------|-------------------------------|
| **L0** | 只读 | 对用户当前页做只读观测:快照、选区、(pro 中)extract。零状态改变 | `activeTab`(仅只读命令) | 否 | `readonly` |
| **L1** | 低危写 | 只作用于 **本会话自建的专用标签** 的导航/点击/滚动/站内搜索框填写/开关节标签;不产生页面外持久副作用 | `newTab` / `tabId:N` | 否(但动作须逐步验证) | `low` |
| **L2** | 确认级 | 触碰账号、身份或会产生真实世界后果的写:登录/登出、填个人数据、提交表单、授权 OAuth、改账号设置 | `newTab` / `tabId:N` | **是**:逐条列出将写的内容与目标,等用户显式"确认"字样后执行 | (skill 内不预设;动态升级) |
| **L3** | 高危屏蔽 | 花钱、对外发声、不可逆破坏:购买/支付、发布/评论/转发、删除、提交报考等敏感数据、下载可执行文件 | — | **永不执行**:即使用户显式要求,也只产出文本草稿/操作指引,由用户人工完成 | (禁止出现在 skill 中) |

## 2. L3 高危动作清单(屏蔽清单)

以下动作在**任何 skill、任何通道**中被触发时必须拒绝执行并说明;Agent 不得以"用户明确要求"为由升级:

| # | 动作类别 | 典型例子 | 说明 |
|---|----------|----------|------|
| 1 | 购买/支付 | 下单、加购物车并结算、支付、领券核销 | 资金后果不可逆;比价 skill 只产出对比与待确认清单 |
| 2 | 发布/对外发声 | 发帖、评论、转发、举报、发邮件、发弹幕 | 以用户身份对外产生内容 |
| 3 | 提交个人数据 | 填姓名/手机号/身份证/考号/住址并提交任何表单 | 志愿填报系统、报名系统、简历投递均属此列 |
| 4 | 删除/不可逆修改 | 删帖、删评论、清空回收站、注销账号、改绑定 | 不可逆 |
| 5 | 账号与会话 | 登录、登出、改密码、授权第三方 OAuth | 凭据进入浏览器会话即属 L2,授权动作属 L3 |
| 6 | 下载与执行 | 下载 .exe/.apk/脚本并运行 | 供应链风险 |
| 7 | 绕过访问控制 | 绕过反爬/验证码/付费墙/登录墙、伪造 UA/指纹 | 原则红线,连同"尝试"都禁止 |

注:登录(L2)与 OAuth 授权(L3)边界——输入用户已有凭据属 L2 须确认;任何"第三方代登录/共享凭据/验证码转发"一律 L3。

## 3. L2 确认级动作清单(须显式确认)

| # | 动作 | 确认话术要求 |
|---|------|--------------|
| 1 | 在受控浏览流程中登录用户已声明的账号 | 逐条列出:目标站点、将填写的字段数、是否勾选"记住我";密码字段必须 `fill(secret=true)`(结果不回显) |
| 2 | 填写非敏感但会提交的表单(如订阅、问卷调查) | 列出全部将提交字段与提交按钮文案 |
| 3 | 账号内设置变更(默认地址、偏好开关) | 列出变更前→变更后取值 |
| 4 | 上传用户本地文件到站点 | 列出文件名、目标站点、可见范围 |

确认协议:一次只列一批动作;用户回复含"确认/确认执行"字样方可继续;用户沉默/岔开话题 = 不确认;确认后执行仍须逐步验证,失败即停。

## 4. target 与 write_level 的强制矩阵

| write_level | 允许 target | 允许工具面(⊆ CONTRACT §b) | 备注 |
|-------------|-------------|------------------------------|------|
| `readonly` | `["activeTab"]` | snapshot(+get_tabs 受限);readonly 构建下由 §a.4 矩阵兜底 | 代表:ask-on-page |
| `low` | 必含 `newTab`;可含 `activeTab`(仅其中只读命令) | 导航/快照/抽取/专用标签内的 click/fill(非敏感)/scroll/wait/screenshot | 代表:compare-prices、structured-table、verify-claims |
| `high` | 同上 | 预留:接入 L2 确认协议后的受控浏览 skill | 本轮无 skill 使用,仅作接口预留 |

强制点(与 CONTRACT §a.3 双保险):
- skill 声明只是**意图层约束**;真正的硬闸在扩展侧(`activeTab` 写命令 → `TARGET_DENIED`;未托管 tabId → `TARGET_DENIED`)与 readonly 构建矩阵(`READONLY_REJECTED`)。
- AI 客户端通过 MCP 调用时不允许传 `activeTab` 给写类工具(daemon 拒绝)。
- skill 的 `invariants` 必须复述"绝不在用户当前标签 navigate/点击"一类硬约束,作为 prompt 话术层第三道闸。

## 5. prompt.md 护栏三件套(逐 skill 必写)

每个 skill 的 `prompt.md` "安全护栏"节必须包含以下三类条目,缺一即测试失败:

1. **只读默认**:能用只读完成的绝不写;列出本 skill 的最小工具面。
2. **写动作分级确认**:写明本 skill 何时会触发 L2,以及确认话术格式;无 L2 场景的 skill 写明"不涉及,遇到即转介"。
3. **高危屏蔽**:逐条引用第 2 节 L3 清单中与本 skill 相关的条目,写明拒绝口径。

## 6. 执行→验证→重试 的安全语义

- 每个动作:执行 → 按 skill `verification_rules` 验证 → 失败重试 **≤2 次** → 仍失败则**中止并说明**,不静默跳过、不降级为猜测(CONTRACT §g.2 AGENT_06 条)。
- 重试不得改变动作的级别:失败的低危动作重试仍是低危;**任何失败都不允许"顺手升级"为 L2/L3 动作来绕过**。
- `REF_STALE`:重新 snapshot 后方可重试,禁止盲点旧 ref。
- 被拦截(反爬/验证码/登录墙/付费墙):视同该路径不可用,如实标注,不进入第 2 节 #7 绕过清单。
