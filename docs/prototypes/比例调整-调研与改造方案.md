# Moirca「院校比例调整」前端调研与改造方案

> 调研人:ClawsGO Agent · 2026-09-07 · 配套交互原型:`Moirca比例调整-交互原型.html`(双击即开,无需构建)

## 一、现状诊断(基于 tmp/Moirca 实际代码)

| 现状 | 位置 | 问题 |
|---|---|---|
| 冲稳保比例**完全由后端定死** | `recommendation.py:386`(按分数差分类) | 用户无法表达"我想更激进/更稳妥" |
| 前端只有**只读计数条** | `VolunteerTable.tsx:88-97`(`冲 8 稳 4 保 3` 纯文字) | 看得见、调不了——"单调"的直接来源 |
| 推荐请求**没有比例参数** | `ScoreInputBar.tsx:86-91`(只有 score/province/keywords/top_n) | 想调也传不进去 |
| AHP 对比**只支持 2 个候选** | `AHPMatrix.tsx:47-55`(自动取前 2 个收藏) | 5 维滑块是"两两对比",不是"多校之间分配" |
| AHP 权重计算**是假的** | `AHPMatrix.tsx:135-165`(每维固定 0.2 权重,CR 是绝对值凑数) | 名为 AHP 实为均权,雷达图好看但不科学 |

结论:比例调整链路(用户意图 → 请求参数 → 后端分类 → 前端反馈)四环里断了三环,只剩展示。

## 二、GitHub 同类项目调研

**高考志愿类**
- [YSblack/Destiny](https://github.com/YSblack/Destiny):冲稳保按**录取概率阈值**划分(冲 15-70% / 稳 70-90% / 保 90%+),而不是裸分数差——阈值可调就是天然的比例入口。
- [FlySky-z/gaokao-analysis](https://github.com/FlySky-z/gaokao-analysis):Go + Next.js 14 + shadcn/ui + Tailwind,数据分析/志愿推荐/位次转换分模块,响应式;代表这类工具的现代化基线。
- [Pilot1799/Zhangxuefeng-AI-gaokao](https://github.com/Pilot1799/Zhangxuefeng-AI-gaokao):本地知识库 + LLM 咨询,弱结构化比例、强对话式引导——可借鉴它的"偏好追问"式交互。
- [掌上高考数据系项目(relatedrepos 索引)](https://relatedrepos.com/gh/Cabbage-xy/gaokao):Django/SpringBoot+Vue 多个变体,普遍是"表格+筛选"传统布局,无比例交互——Moirca 在这里有机会做出差异。

**比例分配组件(可直接借力)**
- [react-percentages-slider](https://www.npmjs.com/package/react-percentages-slider):**一条堆叠条上拖分割线**分多个扇区(text/color/percentage 数组),正是"冲|稳|保"和"多校权重"的理想形态。
- [react-ratio-inputs](https://www.npmjs.com/package/react-ratio-inputs):多行 `{name, value}` 滑块 + 总和约束(max/min),自带联动归一。
- [shadcn Budget Allocator block](https://www.shadcn.io/blocks/dialog-budget-allocator):分类滑块 + 实时百分比 + **剩余余额追踪 + 预设模板**——"预设 + 剩余提示"值得照抄。
- [gre/multi-slider](https://relatedrepos.com/gh/gre/multi-slider):单轨道多滑块分配,交互最省空间。

**共性设计语言**(所有做得好的分配类 UI):① 总量守恒实时可见(100% 或 N 个志愿);② 预设模板一键起步;③ 拖动时其余项自动补偿,而不是让用户自己凑和;④ 改动立即反映到结果列表/图表。

## 三、改造方案(四环补全)

### 1. 冲稳保三段分配条(替换只读计数条)
- 一条堆叠条,红/蓝/绿三段,两个**可拖分割线**;下方同步显示 `百分比 + 志愿个数`(按志愿容量 45 自动换算)。
- 三个预设按钮:**均衡 30/40/30 · 稳健 20/50/30 · 冲刺 45/35/20**,点按回弹动画。
- 推荐时作为 `ratio: {chong, wen, bao}` 传入 `POST /api/recommend/`(后端把分数差阈值从 ratio 反推)。

### 2. 多校权重分配(补 AHP 只能两两对比的洞)
- 收藏 ≥2 所院校后,每校一行滑块,**拖任意一行,其余按比例自动补偿**,总和恒 100%。
- 顶部堆叠色条实时呈现整体结构;`平均分配 / 按录取概率 / 清空` 快捷键。
- 与 AHP 的关系:两两对比保留(专业场景),多校权重作为轻量日常入口;AHP 的维度权重计算换成真特征向量法(几何平均 + 特征值 CR),见 §4。

### 3. 联动反馈
- 权重变化 → 志愿表实时重排(加权分 = 概率分 × 权重),不需要点"重新推荐"。
- 比例变化超出常识(如保底 < 10%)时,黄条提示"保底不足,风险偏高"(对齐 shadcn block 的 balance warning)。

### 4. 后端配合(小改)
- `recommendation.py` 接收可选 `ratio`,把三档分数差阈值改为由 ratio 反推;缺省维持现行为(向后兼容)。
- `/api/compare/` 的维度权重用 AHP 特征向量法重算,CR < 0.1 才算通过(现在的前端假 CR 可以删了)。

### 5. 落地顺序
1. **纯前端先行**:三段分配条 + 多校权重滑块(原型已验证交互,零后端依赖,改动集中在 `VolunteerTable.tsx` + 新组件 `RatioAllocator.tsx`)。
2. 后端 `ratio` 参数(半天工作量)。
3. AHP 特征向量法替换(独立 PR,带数值测试)。
